{{- if .Values.infra.vault.inCluster }}
Vault: server mode, SEALED and uninitialized until you unseal it (Shamir keys stay
with you). Until then the DevOps Vault console answers 503; nothing else waits on it.
  kubectl -n {{ .Release.Namespace }} exec -ti oshal-vault-0 -- vault operator init
  kubectl -n {{ .Release.Namespace }} exec -ti oshal-vault-0 -- vault operator unseal
Runbook: deploy/helm/oshal/README.md ("Vault runbook").

{{- if .Values.rbac.botLauncher }}
Runtime-launched bots: a bot the controller launches at runtime (an app that brings
its own bot-node) reads oshal-shared-env and the optional oshal-bot-env Secret, not
oshal-shared-secret. Without JWT_SECRET it fails to boot with
"JWT_SECRET must be set in production". Copy the chart Secret's keys into
oshal-bot-env now, and again after you change swarm.jwtSecret or infra.arangodb.root*:
  kubectl -n {{ .Release.Namespace }} create secret generic oshal-bot-env   # only if it does not exist yet
  kubectl -n {{ .Release.Namespace }} patch secret oshal-bot-env --type merge -p "{\"data\":$(kubectl -n {{ .Release.Namespace }} get secret oshal-shared-secret -o jsonpath='{.data}')}"
Details: deploy/helm/oshal/README.md ("Credentials").
