Every app you'd want an assistant for — on hardware you own.

oshal is an orchestration platform for agentic AI. The platform is the part that never changes: a cockpit, a queue, a set of databases, a connector vault, and accountable bot identities that do the work. Applications are what you install on top — each one a packaged bot with its own surface, its own connectors, and its own domain. Find yours below, then look inside the box that runs it.

The application group

Pick the job, not the technology.

Applications are grouped onto shelves by who they serve — not by which model or connector they happen to use. An app bundles the bots, the connector permissions, the ticket types and the cockpit surface it needs, and installs as one unit. Nothing is compiled into the core: install one, install a shelf, or install none of them and use the assistant alone.

No application matches that search.
Installing. Apps install from git and hot-load — node scripts/oshal-app.js install <name> on the host, then the swarm auto-loads it. A one-call install straight from the catalog (POST /api/swarm/apps/install-remote) is planned, not shipped. Uninstall is dependency-aware: it refuses to orphan an app another one depends on.

Inside the box

The platform every one of those apps is standing on.

The apps are the visible part. Underneath, the same nine pieces run for all of them — one cockpit, one queue, one credential vault, one set of databases. An app never ships its own copy; it reaches platform capability by declaring what it needs. Open any box to see what's actually in it.

Watching the work

A dashboard for every layer that can go wrong.

Agent systems fail quietly — a bot stops heartbeating, a queue backs up, a model bill runs away. Each of those has its own surface, and they read from the live tables rather than from a log summary.

Opening it

One app, one shelf, everything, or just the assistant.

The cockpit is shaped by the URL, and the URL is the only source of truth — nothing is cached into your browser to poison the next visit. That means a shape is a link: bookmark it, send it to someone, put it on a kiosk.

/cockpit/ The framework default. Tickets, chat, calendar, dashboard — the ribbon shaped by what you're authorized for, with no app loaded.
/cockpit/?app=<name> One application, full screen: its ribbon, its surfaces, and its ticket list pre-filtered to the ticket types that app registered.
?app=life · ?app=system · ?app=games
A shelf as one desk. These are real apps whose job is to gather related apps behind a single toolbar — the lifestyle desk, the account-infrastructure desk, the game night desk.
?app=jarvis Just the assistant. Ask in plain language; it classifies the request, routes it to the specialist bot that owns that domain, and answers as one voice — or tells you which app needs your screen first.
Local first. The stack runs on one box with Docker — cockpit, Postgres, Redis, the vector store and the bot containers — and scales out to Kubernetes without changing the app contract. Sign-in is OIDC in production; local development runs with a mock identity so a human can always exercise the thing in a browser without an external service being up.
