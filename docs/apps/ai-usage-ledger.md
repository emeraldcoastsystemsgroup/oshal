# AI usage and requirements ledger — core

Generated by `scripts/ai-usage-ledger.js` from every manifest's `rating:` block (`swarm-apps/*.yaml`). Do not edit by hand:
the `--check` gate fails when this file is stale or a manifest has no rating. Field meaning: ADR-170 D2, D9, D10.
Memory is container MiB the application adds to the platform, including any engine container it owns;
`low` runs it, `high` is the ceiling to plan for.

Declared memory (basis `declared`) follows one rule until an observed run replaces it (basis `observed`):
a bot-node container is 64 MiB low ([the sizing runbook](../runbooks/docker-engine-memory-sizing.md) measures 43–50 MiB idle per worker bot),
an inline-only application is 32 MiB low (its load lands in the api process), an engine container is its
runbook idle rounded up to the next 32 MiB, and `high` is 4 × `low`, a declared ceiling rather than a measurement.

Tier is the capability the feature asks of a model today (ADR-170 D1): T1 pick from a set, T2 a bounded plan code
renders, T3 grounded reasoning over retrieved context, T4 long tool loops. A package with no model in the loop is T0.
Tokens per unit and models verified read "not yet measured" / "none recorded" until the P0 and P1 generators exist;
a number in those columns is never typed by hand.
