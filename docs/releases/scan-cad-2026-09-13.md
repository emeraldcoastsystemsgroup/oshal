## Behavior delivered

Changing a job's title, measurements, effective reconstruction settings or capture
inputs now retires its previous report and output files before new results can be
published. A failed rebuild cannot leave the old STL available as if it represented
the new inputs. A validated no-op change retains the current result. Effective
build settings, including request overrides, are persisted with the job.

Job detail, artifact downloads and printer submission use the persisted freshness
state. Stale output returns an explicit refusal even if an old file remains on
disk; a failed mesh check also prevents printing. Current nonprintable geometry
remains available for inspection. The owner checks and explicit print confirmation
remain in place.

Within the current API process, a bounded guard coordinates each owner's job
reads, mutations, rebuilds and print preparation. Conflicting operations are
refused as busy instead of racing. This is **not a distributed lock**: deploying
multiple API writers against the same job storage requires a separate cross-process
coordination design. No multi-writer guarantee is claimed by this release.

The surface clears the old drawing, model, downloads and print controls when inputs
change. Unsaved scale changes require saving before reconstruction. Responses from
an older STL request, rebuild or detail refresh cannot restore obsolete output or
overwrite newer measurement input. The actual WebGL viewer also needed two fixes:
rename its reserved GLSL `flat` uniform and schedule the first draw. Both fixes are
covered by real Chromium shader compilation, triangle draws and shaded pixels.

### Photo-upload identity correction

The published 0.2.1 photo upload lost the core request's AsyncLocalStorage identity
when the multipart parser resumed its callback. The newly guarded job lookup then
correctly denied the identity-less database operation, producing `job_not_found`
even though the authenticated detail request for the same synthetic job returned
200. Native origin logs correlate the denial with that guarded lookup at
01:28:21 UTC. A local reproduction uses actual Express, multer, sharp and the core
identity module, with a SQL double that refuses missing identity; it reproduces
the photo-upload 404 without a printer or production database.

The narrow 0.2.2 correction binds the multipart continuation to
the original async request context for the photo, video and point-cloud upload
routes, retaining the existing owner and freshness guards. Its published source
and exact stage are listed above; five added regression cases pass with the
retained suites. Native photo upload succeeds on the installed correction. The
0.2.1 stage, tests, preparation and activation receipts remain historical evidence;
none is relabeled as 0.2.2 proof. The original preservation baseline remains the
final target after only the disposable native fixture is removed.

## CAD scope and remaining work

The [CAD Studio plan](https://github.com/emeraldcoastsystemsgroup/oshal-applications/blob/905886d6cd17a0d85780efff13d6d12ae65cf80e/scan-to-print/CAD-PLAN.md)
defines a proposed store-owned CAD application and a first editable mounting plate
with four holes: parameter changes, undo, save/reopen and independently reimported
STEP/STL exports. A pinned CadQuery/OpenCascade worker is proposed, not installed.
An optional SOLIDWORKS adapter requires a supported licensed workstation and its
own actual native-document round trip. No general CAD editor, CAD kernel worker
or SOLIDWORKS integration is delivered by Scan 0.2.2.

Current Scan outputs remain STL/OBJ meshes, a six-view overall-dimension SVG and
a report with measurement provenance. They do not contain an editable feature
tree or complete manufacturing tolerances. The planned artifact-source handoff,
depth-image inputs/reprojection, fiducial scaling and printer progress work remain
separate. The current slicer command is unset; no G-code preparation, physical
printer submission or physical-print acceptance was performed for this release.
No provider generation or GitHub Actions execution is claimed.
