This is a point-in-time, no-spin posture map for the OSHAL / Open Swarm harness.
Status values:

- CLOSED: a control is in force today, on by default.
- PARTIAL: a control exists but has a known gap, or is only opt-in.
- OPEN: the control is not in force today; a path to harden may exist but is not engaged.

The hardening modules referenced below live in `src/features/security/hardening/` and are already
wired into `src/app/server.ts` or their owning route. Defaults differ by control: CSP reports by
default, envelope crypto is on by default, the public-origin limiter is always mounted, while CSP
enforcement, internal/cost throttles, fine-grained RBAC, and Alertmanager HMAC require deployment
configuration. The table names each posture rather than treating every module as opt-in.

## Notes on honesty

- A mounted control is not necessarily an enforcing control. CSP is report-only by default;
  internal/cost rate limits, RBAC enforcement, and Alertmanager HMAC remain configuration gates.
- The governance posture API resolves these same active flags (`cspMode`, envelope/key state,
  external/internal/expensive limiter coverage, and HMAC configuration) rather than retired aliases.
- Historical private-repository credential values still require provider-side revocation evidence.
  The current public repository is scan-clean; do not describe an unneeded rewrite of this public
  history as a release prerequisite. See `docs/backlog/hardening.md` #17.
