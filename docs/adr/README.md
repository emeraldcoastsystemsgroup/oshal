# Architecture Decision Records (ADRs)

This directory contains Architecture Decision Records for the OSHAL project. ADRs document significant technical decisions with their context, rationale, and consequences.

## What is an ADR?

An ADR captures a key decision that affects the project's architecture, tooling, or development practices. Once accepted, ADRs are immutable. If a decision is reversed, a new ADR is created that supersedes the original.

## Template

```markdown
# ADR-NNN: [Title]

## Status
Proposed | Accepted | Deprecated | Superseded by ADR-NNN

## Context
What problem or situation triggered this decision? What constraints exist?

## Decision
What did we decide to do?

## Consequences
What are the trade-offs? What becomes easier? What becomes harder?
```

## When to Write an ADR

- Framework or library selection
- Architecture pattern changes
- Migration strategies
- Breaking API changes
- Infrastructure decisions
- Significant tooling changes
